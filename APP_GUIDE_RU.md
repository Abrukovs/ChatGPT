# Журнал спортивных прогнозов — запуск и работа

Рабочее приложение на Python + Streamlit, без платных API. Репозиторий: [Abrukovs/ChatGPT](https://github.com/Abrukovs/ChatGPT).

## Быстрый запуск на Windows

1. Установите **Python 3.12** с [python.org](https://www.python.org/downloads/windows/). При установке отметьте **Add python.exe to PATH**.
2. На странице репозитория нажмите **Code → Download ZIP**. Распакуйте архив в отдельную папку.
3. Дважды нажмите **start_windows.bat**. При первом запуске он установит бесплатные зависимости; это может занять несколько минут.
4. Откроется браузер с приложением. Если не открылся, перейдите на **http://localhost:8501**. Окно командной строки оставьте открытым. Закрытие окна останавливает приложение.

Другой способ, через PowerShell в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Для Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

## Первое использование

- В боковой панели выберите **GitHub**: приложение прочитает публичный журнал. Без токена ничего не запишет.
- Для проверки без GitHub выберите **Локально**. Новые данные появятся в `data/` рядом с приложением. Этот режим не отправляет их в GitHub. Для переноса загрузите `data/imported_predictions.csv` через раздел «Файл», проверьте строки и сохраните в режиме GitHub. Результаты для них проверяются отдельно.
- Откройте **Импорт**, вставьте итоговый ответ и нажмите **Распознать**.
- Проверьте таблицу. Отметьте нужные строки в столбце **Сохранить**. `role=final` означает окончательный прогноз; `alternative` — альтернативу; `preliminary` — рассуждение. Альтернативы можно сохранить только после явного перевода в `final` при ручной проверке.
- Даты, если известны, указывайте `ГГГГ-ММ-ДД`. Если даты нет в источнике, оставьте пустой: приложение ничего не придумывает. Неполные записи не рассчитываются автоматически.
- Проверьте исходные фрагменты, отметьте подтверждение и нажмите **Подтвердить и сохранить**.
- В **Журнале** доступны фильтр по спорту, CSV и Excel. Во вкладке **Статистика** — разбиение по спорту, категории и точному названию рынка.

### Авторизация для записи

Токен нужен самому приложению на вашем компьютере; подключение GitHub в ChatGPT автоматически ему не передаётся.

1. Откройте [создание fine-grained token](https://github.com/settings/personal-access-tokens/new).
2. Назовите токен `Sports journal`, задайте срок действия, выберите владельца `Abrukovs`.
3. **Repository access → Only select repositories → ChatGPT**.
4. **Repository permissions → Contents → Read and write**. Другие разрешения приложению не нужны.
5. Нажмите **Generate token**, скопируйте токен и вставьте в скрытое поле **GitHub token** в боковой панели приложения. Не отправляйте его в чат и не добавляйте в файлы проекта.

Токен находится только в памяти сессии. Перезагрузка браузера может потребовать повторного ввода. Альтернатива для собственного сервера — переменная окружения `GITHUB_TOKEN` и обязательный `APP_PASSWORD`. Поддерживается `.streamlit/secrets.toml`, который исключён из Git. **Токен не выводится в ошибки и не сохраняется в CSV.**

Если используются серверные Secrets:

```toml
GITHUB_TOKEN = "вставьте_свой_токен_только_в_Secrets"
APP_PASSWORD = "задайте_длинный_случайный_пароль"
```

Без `APP_PASSWORD` приложение с серверным токеном закрывает доступ. Для сайта можно оставить токен незаданным и вводить его отдельно в своей сессии. Не давайте посторонним пароль приложения, использующего общий токен.

## Поддерживаемый импорт

1. **Текст:** Markdown-таблицы с колонками «Матч», «Рынок»/«Лучший рассмотренный рынок», «Вероятность», «Категория» и/или блоки «ключ: значение». Свободный текст без явной структуры попадает в ручную проверку.
2. **CSV/TSV:** русские или английские названия столбцов, разделитель запятая, точка с запятой или табуляция; UTF-8. Образец — `examples/predictions.csv`.
3. **JSON:** объект, список объектов, стандартный ChatGPT `conversations.json` с `mapping/current_node` или простой формат `messages` с `role/content`. В ChatGPT обрабатывается только текущая ветка и ответы assistant, сообщения пользователя и другие ветки исключены. Дата сообщения переводится в московскую дату; дата матча не выводится из даты сообщения.
4. **TXT/MD/HTML:** текстовые итоговые ответы. Архив ZIP экспорта предварительно распакуйте. Двоичные PDF, DOCX и изображения не распознаются.
5. **Публичная ссылка ChatGPT:** только `https://chatgpt.com/share/ID`. Запрос без cookies, авторизации и переходов по редиректам. Если страница закрыта, требует JavaScript или не содержит явно доступных ответов assistant, приложение предлагает текст/JSON. Авторизация не обходится. Ссылки других нейросетей заменяйте текстом или файлом.

Максимальный размер файла — 25 МБ. Большие экспорты разделите на части. Приложение не использует нейросетевой API и не обещает универсально понимать любой стиль ответа. Нераспознанные поля остаются пустыми. Для надёжного импорта можно просить нейросеть заканчивать ответ таким блоком:

```text
Дата прогноза: 2026-10-23
Дата матча: 2026-10-23
Вид спорта: футбол
Чемпионат: Ligue 1
Матч: Брест — Ницца
Рынок: Ницца ИТМ 1,5 · 1.53
Вероятность: 69%
Категория: B
Тип: итог
Аргументы: ...
Риски: ...
```

Это пример формата, а не новая рекомендация. В `examples/` есть TXT, CSV и JSON на основе ранее предоставленной итоговой таблицы пользователя. Они **не добавлены в рабочий журнал**.

## Сохранность данных и дубликаты

- `predictions.csv`, `daily_decisions.csv`, `settlements.csv` и их первоначальные прогнозы приложение не изменяет.
- Импорт: `data/imported_predictions.csv`. Проверенные результаты: `data/imported_results.csv`. Единый журнал объединяет все источники при чтении.
- Перед записью все выбранные строки проверяются; некорректная строка останавливает весь импорт.
- Повтор определяется по нормализованным датам, спорту, матчу, рынку и линии. Категория, коэффициент и источник не создают новую версию уже записанного прогноза. Первоначальная запись сохраняется.
- При обеих неизвестных датах в идентификатор также входит исходный фрагмент. Перевод названий команд или иная формулировка рынка могут помешать точному сопоставлению: такие повторы проверяйте вручную в предпросмотре. Автоматического нечёткого объединения разных прогнозов нет.
- Запись в GitHub использует SHA версии файла. При конфликте приложение перечитывает файл и повторяет добавление до трёх раз. После записи перечитывает журнал и проверяет записанные поля. Токены и оригинальные полные экспорты не коммитятся.
- В GitHub сохраняется исходный фрагмент выбранной строки/блока. Репозиторий сейчас публичный: перед подтверждением проверьте фрагменты на личные данные.
- Сначала скачайте CSV/Excel, если хотите резервную копию. Для переноса приложения достаточно клонировать репозиторий и установить зависимости. При локальной работе перенесите и папку `data/`.

## Результаты и статистика

Вставленный `WIN/LOSS` сохраняется в `reported_status` как заявление источника. Фактический `status` остаётся `PENDING` до независимой проверки. Это предотвращает попадание непроверенных побед в статистику.

Существующий `khl-auto-results.yml` по-прежнему проверяет старый `daily_decisions.csv` своим механизмом Webcaster. Новый `tracker-results.yml` отдельно проверяет импортированные записи ежедневно в **11:45 по Москве** и сохраняет только `data/imported_results.csv`. Его можно запустить через **Actions → Imported KHL results → Run workflow**: по умолчанию только проверка, для записи включите `write`.

Новый адаптер повторно использует существующие `events_for_day`, `parse_market`, `assess`. Поддержка намеренно узкая: индивидуальный тотал за основное время, точная английская формулировка `SKA team total under 3.5 goals in regulation`, точные команды, уникальное завершённое событие, стадия 407, счёт по трём периодам и линия с `.5`. Для этого адаптера **event_date — дата матча в Europe/Riga**, как в существующем механизме; дата прогноза из экспорта — по Москве. При другой временной зоне проверку не запускайте, сначала сверьте дату в Риге. Отсутствующая дата, неподдерживаемый рынок, другой сезон/стадия, неоднозначность или сбой API оставляют `PENDING`. Целые тоталы не рассчитываются этим адаптером, чтобы не перепутать PUSH и LOSS. Рынки победы, форы, тоталы матча и другие виды спорта ожидают отдельного проверенного адаптера.

### Добавление бесплатного источника

Реализуйте `ResultProvider.verify(row)` из `tracker/results.py`. Возвращайте `None` при любой неопределённости. Для результата нужны ID прогноза, `WIN/LOSS/PUSH/VOID`, счёт, HTTPS-ссылка источника, время проверки и объяснение расчёта. Сверяйте команды, дату и зону времени, статус завершения, основное/добавленное время, ОТ/буллиты и правила рынка. Перед подключением добавьте тесты на возврат, отмену, одинаковые команды в разные даты и неподтверждённый счёт. Подключите адаптер в `verify_pending`. Произвольные URL не выполняются как код.

`WIN %` считается только из WIN и LOSS; PASS, PUSH, VOID и PENDING не участвуют в знаменателе. ROI — **условная модель по одной единице на запись с известным ориентировочным коэффициентом**, с нулём при PUSH и исключением VOID; это не фактическая прибыль и не отчёт по денежным ставкам.

## Бесплатное размещение

Streamlit Community Cloud поддерживает это Python-приложение бесплатно. Sites/Cloudflare Workers не запускают Python + Streamlit, поэтому приложение не заменено статической демонстрацией.

1. Откройте [share.streamlit.io](https://share.streamlit.io/) и войдите через GitHub.
2. Нажмите **Create app / New app → Deploy a public app from GitHub**.
3. Repository: **Abrukovs/ChatGPT**; Branch: **main**; Main file path: **app.py**.
4. В **Advanced settings** выберите Python **3.12**.
5. Можно оставить Secrets пустыми: приложение будет читать публичные данные, а ваш токен вводится в скрытом поле сессии. Для общего серверного токена задайте одновременно `GITHUB_TOKEN` и `APP_PASSWORD`, как выше.
6. Нажмите **Deploy**. Полученную ссылку сохраните. После коммитов в main приложение обновляется из GitHub.

Локальный режим на бесплатном хостинге не даёт долговечного хранения: для постоянного журнала используйте GitHub. Самостоятельное чтение закрытых ChatGPT-чатов не включено: передавайте итоговые ответы, публичные ссылки или экспорт.

## Тесты и неполадки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

- `403`: проверьте права/срок токена и лимит GitHub.
- `404`: проверьте ветку `main` и доступ к репозиторию; отсутствие нового журнала до первого импорта допустимо.
- Конфликт записи: обновите журнал и повторите. Уже записанные строки пропустятся.
- Нераспознанный ответ: используйте блок с явными полями или заполните предпросмотр вручную.
- Недоступная ссылка: вставьте текст, не пытайтесь открыть её с чужими cookies.
- Ошибка API результата: запись остаётся PENDING. Не заменяйте её на WIN вручную без проверки.
- Для обновления при установке через ZIP скачайте новую версию в другую папку, перенесите локальный `data/`, затем запустите BAT. Если журнал хранится в GitHub, он подгрузится сам.

Исходные GitHub Actions сохранены. Исправлена только опечатка существующего теста `test_away_total`: указанная линия приведена к линии его же рынка (2.5 вместо значения по умолчанию 3.5). Расчёт старых результатов не изменён.

Официальные справочники: [Streamlit Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud), [Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management), [GitHub Contents API](https://docs.github.com/en/rest/repos/contents).
